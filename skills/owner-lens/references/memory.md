# 기억 — 챗에서는 사용자가 들고 다닌다

이 스킬은 챗에서 돈다. **대화가 끝나면 아무것도 남지 않는다.**
그래서 기억은 스킬이 아니라 사용자가 보관한다.

산출물을 두 갈래로 나눈다. 섞으면 기밀이 새거나, 낡은 판단이 고착된다.

| | 회사 카드 | 인사이트 원장 |
|---|---|---|
| 범위 | 한 회사 | 회사와 무관 |
| 기밀 | 포함 가능 | **절대 불가** |
| 보관 | 그 회사 폴더 / 개인 노트 | 한 곳에 모아 계속 쌓음 |
| 공유 | 안 함 | 공유 가능 |
| 쓰임 | 다음 미팅 R0에서 붙여 넣기 | 새 회사 분석의 사전 지식 |

---

## 회사 카드

한 회사당 한 장. 대화 마지막에 **복사 가능한 블록**으로 낸다.
다음 대화 R0에서 그대로 붙여 넣으면 이어서 진행한다.

서식은 [`templates/company-card.md`](../templates/company-card.md).

### 반드시 남길 것

- **기각된 가설** — 이걸 안 남기면 다음에 똑같은 가설을 또 세운다
- 각 판단의 근거 등급
- 최종 갱신일 — 6개월 지난 카드는 신선도를 의심한다

---

## 인사이트 원장

회사에 묶이지 않는, **전이 가능한 배움**만 적는다.

서식은 [`templates/insight-ledger.md`](../templates/insight-ledger.md).

형식:

```
조건 → 관찰 → 전이 범위 → 검증 상태
```

예:

```
"PE 보유 · 회수 3년 이내"
  → "장기 ROI 안건은 재무 라인에서 멈춘다"
  → 전이 범위: 동일 소유구조에 한함
  → 검증: [1회 관찰, 미검증]
```

### 검증 상태를 반드시 붙인다

| 상태 | 조건 |
|---|---|
| `[1회 관찰, 미검증]` | 한 건에서만 봤다 |
| `[2회, 잠정]` | 서로 다른 건에서 두 번 |
| `[확인됨]` | 서로 다른 건에서 3회 이상, 반례 없음 |
| `[반례 있음]` | 어긋난 사례를 함께 적는다 |

**1회 관찰을 법칙처럼 쓰지 않는다.** 이걸 지키지 않으면 원장이 한쪽으로 치우친 기록이 된다.

## PURGE 규칙 ★

다음은 회사 카드에만 두고 **인사이트 원장에 절대 올리지 않는다.**

- 고객사명
- 담당자를 특정할 수 있는 정보
- 가격·계약 조건
- 비공개로 들은 내부 사정

### 삭제는 파생물까지 따라가야 한다

회사명을 지웠는데 남은 문장이 그 회사를 특정할 수 있으면 **지운 것이 아니다.**

원장에 올리기 전 반드시 자문한다.

> **이 문장만 보고 어느 회사인지 좁혀지는가?**

좁혀지면 둘 중 하나를 한다.

1. 조건을 더 일반화한다 — `"○○ 산업 장비사"` → `"고객 3곳에 매출 70% 이상 의존하는 제조사"`
2. 버린다

### 좁혀지는 예시

```
나쁨: "수주 잔고 ○천억인데 견적 인력이 △명뿐인 회사가 있었다"
      → 업계 사람이면 어디인지 안다

좋음: "수주 규모 대비 견적 인력이 극단적으로 적은 조직에서는
      견적 리드타임이 병목이 되고, 그 병목은 재무제표에 안 나타난다"
      → 조건만 남고 회사는 사라졌다
```

## 카드를 이어 쓰는 흐름

```
1회차 대화
  R0~R4 진행 → 회사 카드 v1 출력 → 사용자가 저장

미팅

2회차 대화
  R0에서 카드 v1 붙여 넣기
  → 미팅 결과 입력 (post-meeting.md)
  → 가설 대조, 기각된 가설 기록
  → 회사 카드 v2 출력
  → 원장에 올릴 항목 별도 출력
```

카드가 있으면 R1(거친 초안)을 건너뛴다. 이미 초안이 있는 셈이다.
대신 **카드가 낡았는지 먼저 확인한다.** 최종 갱신일이 6개월을 넘으면 신호부터 다시 받는다.
