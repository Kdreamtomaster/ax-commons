# 용어집

**한 단어는 한 뜻으로만 쓴다.**

여기서 만드는 건 AI에게 주는 규칙이다. 규칙의 단어가 모호하면 모델이 다르게 해석한다.
사람은 맥락으로 넘어가지만 모델은 그러지 않을 수 있다.
그래서 **용어 일관성은 여기서 품질 문제가 아니라 동작 문제다.**

> 이 문서가 생긴 경위는 [#23](https://github.com/Kdreamtomaster/ax-commons/issues/23)에 있다.
> AI 검토를 여러 번 통과한 문서에서 같은 개념이 세 가지 말로 불리고 있었다.

## 자리 전용 언어를 공용 규칙에 쓰지 않는다

이 도구는 세 자리를 모두 지원한다.
그런데 **한쪽 관점의 말이 공용 규칙에 들어가면 나머지 둘에게 안 맞는다.**

| 쓰지 않는 말 | 왜 | 대신 |
|---|---|---|
| 팔린다 / 안 팔린다 | ① 파는 쪽 관점 | 통과 / 통과되지 않음 |
| 수주 / 클로징 | ① 관점 | 진행 / 착수 |
| 벤더 관리 | ② 관점 | 협력 / 조율 |
| 위에서 시킨다 | ③ 관점 | 요청받는다 |

실제로 임기 게이트 판정이 `팔린다` 였던 적이 있다.
"세 자리를 다 지원한다"고 써 놓고 규칙 언어는 ① 전용이었다.
→ [디스커션 #18](https://github.com/Kdreamtomaster/ax-commons/discussions/18)의 구체적 증거였다.

## 근거 등급 표기

**항상 대괄호로 감싼다.** 문장마다 붙인다.

```
[사실]  [추론]  [가설]  [모름]  [기밀]
```

검증 상태도 대괄호로 쓴다.

```
[1회, 미검증]  [2회, 잠정]  [확인됨]  [반례 있음]  [반증됨]
[반입, 내 조건 미검증]
```

개입 판정은 대괄호를 쓰되 셋뿐이다.

```
[대체]  [저감]  [불가]
```

## 모드 이름

사용자에게는 **① ② ③** 만 보인다. `A`~`F` 는 내부 이름이다.

| 겉 | 안 | 무엇 |
|---|---|---|
| ① 파는 쪽 (AX 회사) | A | 제안 준비 |
| ② 사는 쪽 (AX 추진 조직) | B / C | 자사 진단 / 제안 검증 |
| ③ 일하는 쪽 (현업) | E | 현업 관점 |
| — | D | 자료 재구성 (시점으로 정해짐) |
| — | F | 대립 검토 (시점으로 정해짐) |

문서에서 `모드 A` 라고 쓰지 않는다. `① 파는 쪽 → A 제안 준비` 처럼 겉이름을 앞세운다.

## 고칠 때

용어를 바꾸면 **여덟 군데로 퍼진다.**

```
skills/  →  prompts/  →  dist/ 8종  →  examples/
```

`skills/` 와 `prompts/` 를 고치고 `python3 scripts/build.py` 를 돌린다.
그리고 `examples/` 에 옛 표현이 남았는지 직접 확인한다. **빌드가 예시까지는 안 고친다.**
